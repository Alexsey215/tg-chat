# Telegram-чат на GREEN-API

Тестовое задание: веб-интерфейс для отправки и получения текстовых сообщений в Telegram через [GREEN-API](https://green-api.com/telegram). Внешний вид — по мотивам [web.max.ru](https://web.max.ru).

Демо: https://USERNAME.github.io/tg-chat/

## Как пользоваться

1. В [консоли GREEN-API](https://console.green-api.com) создать инстанс Telegram и авторизовать в нём аккаунт.
2. В настройках инстанса включить получение уведомлений о входящих сообщениях, URL вебхука оставить пустым — иначе уведомления уйдут на вебхук, а не в очередь HTTP API.
3. Войти в приложение по `idInstance` и `apiTokenInstance`.
4. Создать чат по номеру получателя и написать сообщение.
5. Ответ собеседника появится в этом же чате.

## Запуск

```bash
pnpm install
pnpm dev      # http://localhost:5173
pnpm test
pnpm build
```

## Стек

React 19, TypeScript, Vite, Tailwind CSS 4, shadcn/ui (Radix), Zustand, Vitest. Структура по Feature-Sliced Design.

```
src/
  app/        точка входа, стили и тема
  pages/      login, chat
  widgets/    chat-sidebar, chat-window
  features/   auth, create-chat, send-message, receive-messages
  entities/   session, chat, message
  shared/     api-клиент GREEN-API, ui-компоненты, утилиты
```

## Как устроено

- **Вход.** Данные проверяются через `getStateInstance`, пускаем только при статусе `authorized`. Хост API вычисляется из первых четырёх цифр `idInstance`.
- **Отправка** — `SendMessage` на `<номер>@c.us`. Сообщение сразу появляется в ленте со статусом «отправляется», дальше «отправлено» или «ошибка». Неотправленное можно повторить кликом по значку.
- **Получение** — long polling: `ReceiveNotification` с `receiveTimeout=20`, обработка, `DeleteNotification`. Уведомление удаляется из очереди в любом случае, иначе очередь встанет. При сетевой ошибке — повтор через 5 секунд, в шапке показывается, что соединения нет.
- **Сопоставление ответа с чатом.** Чат создаётся по номеру, но Telegram присылает входящие с числовым `chatId`. Поэтому первый ответ ищется по `senderPhoneNumber`, а найденный id запоминается для следующих сообщений. Повторно пришедшие уведомления отсекаются по `idMessage`.
- **Чужие чаты.** К инстансу может быть подключён личный аккаунт, поэтому сообщения из чатов, которых нет в списке, не показываются.
- Сессия, чаты и история хранятся в `localStorage`.

## Ограничения

- Токен инстанса хранится в браузере. Для тестового это нормально, в реальном продукте запросы к GREEN-API стоит проксировать через свой бэкенд.
- Очередь уведомлений у инстанса одна: если открыть приложение в двух вкладках, они будут разбирать уведомления друг у друга.
- История — только сообщения, прошедшие через приложение. Только текст, по ТЗ.
